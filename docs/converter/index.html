Start

The tool is a single HTML file. Open script_charts_to_tinyc_pvs.html from the tinyc/utils folder in any browser — no server, no install, and nothing is uploaded anywhere. The conversion happens entirely in your browser.

Already on TinyC and only want to look at your charts? That is the chart editor.

Das Werkzeug ist eine einzelne HTML-Datei. script_charts_to_tinyc_pvs.html aus dem Ordner tinyc/utils im Browser öffnen — kein Server, keine Installation, und es wird nichts hochgeladen. Die Umrechnung passiert vollständig im Browser.

Schon auf TinyC und willst nur deine Diagramme ansehen? Dafür gibt es den Diagramm-Editor.

The four stepsDie vier Schritte

1 · Read the data.csv1 · data.csv einlesen

Download data.csv from the old device's file manager (http://<device>/ufsd) and pick it here. Easier: enter the IP in step 2, then a ready-made link to the file appears there.

The layout is detected from the line and column counts, so you do not have to say which script wrote it.

Die data.csv im Dateimanager des alten Geräts (http://<geraet>/ufsd) herunterladen und hier auswählen. Bequemer: in Schritt 2 die IP eintragen, dann steht dort ein fertiger Link auf die Datei.

Das Layout wird an den Zeilen- und Spaltenzahlen erkannt, du musst also nicht angeben, welches Script sie geschrieben hat.

2 · Enter the baselines2 · Basiswerte eintragen

dval, mval, yval and the feed-in twins are the counter zero points. In the Scripter they are p: variables in the Tasmota settings and therefore not in the data.csv. Without them the program computes every running bar as

sml_dcon[today] = meter reading − sml_dval

and with sml_dval at 0 that puts the whole meter reading into today's bar — it shoots up to something like 45,000 kWh and squashes the entire imported history onto the zero line.

Enter the IP of the old device, click the generated link, copy the answer back into the field. A link you click is a normal navigation, so the same-origin rule that blocks a fetch from a local file does not apply — no USE_CORS needed.

http://<ip>/cm?cmnd=script?dval;mval;yval;da
http://<ip>/cm?cmnd=script?dval2;mval2;yval2

Leave the fields empty and the file is written without the baseline block. Then press Reset day/month/year consumption once on the device: the history survives, only the running day and month start at 0.

dval, mval, yval und die Einspeise-Zwillinge sind die Zähler-Nullpunkte. Im Scripter sind das p:-Variablen in den Tasmota-Einstellungen und stehen deshalb nicht in der data.csv. Ohne sie rechnet das Programm jeden laufenden Balken als

sml_dcon[heute] = Zählerstand − sml_dval

und bei sml_dval = 0 landet der komplette Zählerstand im heutigen Balken — der schießt auf z. B. 45.000 kWh hoch und drückt die ganze importierte Historie auf die Nulllinie.

IP des alten Geräts eintragen, auf den erzeugten Link klicken, die Antwort ins Feld zurückkopieren. Ein angeklickter Link ist eine normale Navigation — die Same-Origin-Sperre, die ein fetch aus einer lokalen Datei blockiert, greift dort nicht. Es braucht also kein USE_CORS.

http://<ip>/cm?cmnd=script?dval;mval;yval;da
http://<ip>/cm?cmnd=script?dval2;mval2;yval2

Bleiben die Felder leer, wird die Datei ohne Basiswert-Block geschrieben. Dann auf dem Gerät einmal Tages/Monats/Jahres-Verbrauchswerte zurücksetzen drücken: die Historie bleibt, nur der laufende Tag und Monat fangen bei 0 an.

Installing — the order mattersEinbauen — die Reihenfolge zählt

  1. Stop the slot: Tools › TinyC Console › the red ■
  2. Upload the file(s): Tools › Manage File system › Upload
  3. Start the slot: Tools › TinyC Console › the green ▶

If the slot is still running while you upload, saveVars() rewrites the .pvs before the .bin is read. The program imports the .bin once, writes it into the .pvs and then deletes it — the file being gone is the "already imported" marker. The log then says:

sml_chart: .bin carried baselines
sml_chart: imported .bin into .pvs, /sml_chart.bin deleted
  1. Slot stoppen: Tools › TinyC Console › das rote ■
  2. Datei(en) hochladen: Tools › Manage File system › Upload
  3. Slot starten: Tools › TinyC Console › das grüne ▶

Läuft der Slot beim Hochladen noch, schreibt saveVars() die .pvs neu, bevor die .bin gelesen wird. Das Programm importiert die .bin einmal, schreibt sie in die .pvs und löscht sie danach — dass die Datei weg ist, ist die Markierung „schon importiert". Im Log steht dann:

sml_chart: .bin carried baselines
sml_chart: imported .bin into .pvs, /sml_chart.bin deleted

What carries over exactly — and what does notWas exakt übernommen wird — und was nicht

The bars for day and month, consumption and feed-in alike. They are indexed by day and month, so every row is a 1:1 copy (Scripter arrays are 1-based, TinyC puts day 1 at index 0 — that cancels out).

The 4 h / 24 h curves arrive rotated. Their ring position (sml_s4h_pos / sml_s24h_pos) lives in the .pvs and is not part of the .bin. After four resp. 24 hours that has sorted itself out.

wval / wval2 (weekly values from 2_SML_Chart_PV3) have no counterpart in sml_chart_common.tc and are dropped.

Die Balken für Tag und Monat, Verbrauch wie Einspeisung. Sie sind nach Tag bzw. Monat indiziert, deshalb ist jede Zeile eine 1:1-Kopie (Scripter-Arrays sind 1-basiert, TinyC legt Tag 1 auf Index 0 — das hebt sich auf).

Die 4-h/24-h-Kurven kommen verdreht an. Ihre Ringposition (sml_s4h_pos / sml_s24h_pos) liegt in der .pvs und steht nicht in der .bin. Nach vier bzw. 24 Stunden hat sich das von selbst erledigt.

wval / wval2 (Wochenwerte aus 2_SML_Chart_PV3) haben in sml_chart_common.tc kein Gegenstück und entfallen.
